## H. Frozen ControlSim DC-SoC semantics

- Defaults: `eps=2.0`, `min_samples=3`.
- Input order: sorted node IDs.
- Distance: all-pairs shortest-path hop distance on original physical edges;
  disconnected distance is `n+1`.
- DBSCAN noise joins its nearest established cluster, then lowest cluster-label
  tie; if no cluster exists, all nodes form cluster 0. IDs are normalized.
- CORE: highest original physical degree, tie to lowest node ID.
- Structure: each non-CORE is a direct leaf of its cluster CORE; sorted cluster
  COREs form a directed chain. The first CORE is the unique MASTER/root.
- CORE forwards to all active children except the immediate sender. TAIL only
  targets its parent; after receiving from it, sender exclusion makes it
  terminal. Structural relations are logical overlay edges and need not be
  physical neighbors.
- Numeric fanout is irrelevant. Missing/inactive targets are filtered.
- Standalone construction has no AHBN controller. Duplicate receipt does not
  refanout.

## I. Existing Kubernetes behavior and semantic gaps

Before K3.4 the generator recognized only AHBN, Gossip, and Structured. It used
contiguous fixed clusters, configured source (normally 0), and the peer's
fallback path would treat an unknown strategy like AHBN. No DC-SoC roles or DAG
were serialized. Therefore clustering, source, forwarding, isolation, and
fanout behavior all differed from ControlSim.

## J–W. Reconciled static semantics

`app/gen_topology.py` now constructs deterministic density clusters and emits
CORE/TAIL roles, parents, children, CORE neighbors, structural edges, frozen
parameters, the MASTER source, and `dynamic_maintenance=false`.
`app/peer.py` has a separate early DC-SoC dispatch branch. It never calls
Gossip sampling, standalone Structured selection, or AHBN adaptation. COREs
forward every eligible child without a budget. TAILs only uplink to their
parent; sender/self and unavailable targets are removed. The existing
first-receipt/duplicate early-return behavior is shared unchanged.

The Exp08 DC-SoC config contains no fanout. Delay and overload affect timing
only; neither field invokes clustering or role reconstruction. Exp10/Exp11
remain AHBN configurations and are not declared DC-SoC-ready before K3.5.

## X. Determinism

Sorted node iteration, sorted neighborhoods, deterministic queue expansion,
normalized labels, deterministic nearest-cluster attachment, degree/ID CORE
selection, sorted member children, and sorted cluster chaining yield stable
clusters, roles, and target membership for identical inputs.

## Y–Z. Isolation

Standalone DC-SoC creates no `AHBNParams`, controller, or AHBN state and uses a
no-op observation sink. Its selection branch returns before Gossip, Structured,
or AHBN code. Tests make both random sampling and `cluster_targets` raise if
called. AHBN parameters and fanout bounds do not enter DC-SoC decisions.

## AA. Dynamic-maintenance boundary

No repair trigger, replacement election, rejoin action, periodic update, or
reclustering was added. `dynamic_maintenance=false` is descriptive metadata;
K3.5 owns all lifecycle work. Slow or overloaded peers remain structurally
unchanged and may merely be delayed or filtered after an actual failed send.
