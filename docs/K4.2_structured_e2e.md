## Structured implementation check

Targeted inspection of `app/peer.py`, `app/gen_topology.py`, `tests/test_k3_3_structured.py`, and `tests/test_k3_6_cross_baseline.py` established the frozen implementation:

```text
structure construction entry point: app/gen_topology.py assign_clusters(), then node metadata generation
relationship representation: is_cluster_head, cluster_head_id, cluster_members, gateway_neighbors
source/downstream selection: PeerState.target_peers(strategy == "cluster") -> cluster_targets(sender_id)
head rule: all unique cluster_members + gateway_neighbors, excluding sender/self/unavailable; no fanout argument
member rule: cluster_head_id only, unless it is sender/self/unavailable
gRPC receive path: PeerService.Forward -> PeerState.process_envelope
send path: process_envelope -> target_peers -> daemon threads -> forward_to_peer -> PeerServiceStub.Forward
duplicate path: seen_messages check -> received_duplicate -> return before target_peers
metrics path: received_new latency_ms; forward events; duplicate_count; forward_count; GetStatus seen_count
```

The actual Structured terminology is **cluster head**, **cluster members**, **cluster head ID**, and **gateway neighbours**. It is not the DC-SoC parent/children DAG.

The `strategy == "cluster"` branch calls `cluster_targets(sender_id)` without `fanout`. `random.sample` exists only in Gossip/AHBN branches. Structured initialization sets `ahbn_controller`, `ahbn_state`, and `dcsoc_maintenance` to `None`.
