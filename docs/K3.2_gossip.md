## E. Frozen ControlSim Gossip semantics

Inspected `ahbn/strategies/gossip.py`, `run_one.py`, `run_batch.py`,
`ahbn/simulator.py`, and all three supplied Gossip validation records. The
executable rule is active physical neighbors minus self and the immediate
sender. `fanout=None` returns all eligible candidates. Integer fanout returns
`rng.sample(candidates, min(k,n))`, without replacement. The receive event
passes its immediate `src_id`. First reception forwards; duplicates do not
refanout. Standalone construction uses `controller=None` and
`cluster_manager=None`.

`PeerState.__init__` → `process_envelope` → duplicate early return or
`target_peers(sender_id=envelope.sender_id)` → `forward_to_peer`.

Before repair, standalone Gossip inherited numeric fanout 3 from both the
generator and peer initialization, used process-global `random.sample`, did not

controller, and state objects for every strategy. Exp08 Gossip explicitly
contained the legacy `fanout: 3`. It did exclude the immediate sender before
sampling and did not append structural targets.

## G. Repairs performed

- Gossip fanout is independently optional. Missing fanout serializes as JSON
  `null` and means all eligible peers; an explicit integer remains bounded.
- Candidate construction deduplicates physical neighbors and excludes sender,
  self, and known-unavailable peers before selection.
- Bounded selection uses a peer-local `random.Random(topology_seed)` and
  `sample`, giving deterministic no-replacement replay.
- Non-AHBN strategies create no `AHBNParams`, controller, or AHBN state.
- Exp08 Gossip's legacy fixed fanout was removed; generated fanout is `None`.
- Protobuf status represents unbounded Gossip with the reporting-only integer
  sentinel 0; target selection continues to use `None`.

## H. Isolation and forwarding semantics

Standalone Gossip returns directly from its strategy branch before
`adaptive_update` and `cluster_targets`. Cluster-head/member/gateway metadata
can coexist in topology but is not read for Gossip selection. AHBN EWMA,
observations, score, weight, mode, thresholds, and adaptive fanout do not affect
targets. Overload/delay metadata does not switch its strategy. Known failed
destinations enter `unavailable_neighbors` after a failed/rejected send and are
excluded from later selections. Duplicate reception retains existing metrics
and returns before target selection.
